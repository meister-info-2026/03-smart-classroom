# 학생용 설치 및 사용 매뉴얼 (AI 출입 출석 스마트 교실)

> 이 매뉴얼은 **AI 출입 출석 스마트 교실** 팀에 맞게 예시를 채워 넣은 버전입니다.
> 이 킷의 `.agents/`(rules/skills/workflows/hooks/agents), 핵심 보일러플레이트
> 코드, 그리고 **`AGENTS.md`까지 이미 이 프로젝트에 맞게 준비되어 있습니다** —
> 1단계의 PRD 작성·AGENTS.md 완성 과정은 이미 끝나 있으니 내용을 확인만 하고
> 넘어가면 됩니다(왜 이렇게 채워졌는지는
> `docs/AI출입출석스마트교실-AGENTS-초안-및-보충가이드.md` 참고).
>
> ⚠️ **미리 알아둘 것**: 이 프로젝트는 얼굴 인식(InsightFace)이라는 무거운 AI
> 모델을 씁니다. `yolov8n.pt`처럼 사전 다운로드 없이 그냥 설치하면 실습실 전체가
> 동시에 큰 모델을 받으면서 학내망이 느려질 수 있습니다 — **3단계를 시작하기 전에
> 미리, 한 명이라도 먼저 설치해서 검증**해두는 걸 권장합니다.
>
> 각 단계의 프롬프트/확인 방법은 이 문서를 따르고, 진행 체크만 빠르게 하고 싶다면
> `docs/학생-수작업-로드맵.md` 체크리스트를 함께 씁니다(체크리스트는 범용 버전이니
> 항목 이름만 우리 팀 것으로 바꿔서 사용합니다).

## 0단계. GitHub에서 받기 + 하네스 구축 (팀당 딱 한 번만)

### 0-1. 저장소 받기
팀장(김다온) 또는 백엔드 담당 1명만 하면 됩니다. PowerShell에서:
```powershell
git clone -b classroom [교사가 안내한 GitHub 저장소 주소] AI-출입-출석-스마트-교실
cd AI-출입-출석-스마트-교실
```
Git이 익숙하지 않다면, GitHub 저장소 페이지에서 **브랜치를 `classroom`으로 전환한
뒤 Code → Download ZIP**으로 받아 압축을 풀고 그 폴더로 이동해도 됩니다.

> ⚠️ 반드시 **`classroom` 브랜치**를 받아야 합니다. `main` 브랜치는 여러 팀이 함께
> 쓰는 범용 템플릿이라 이 팀 전용 `AGENTS.md`와 `attendance-tracking-integration`
> 스킬, 얼굴 인식 확장이 들어있지 않습니다.

**확인**: `AGENTS.md`, `.agents/`, `docs/`, `backend/`, `frontend/`, `vision/`, `pi/`가 들어있으면 성공입니다 — 공통 인터페이스(`backend/iot/base.py`, `backend/websocket_manager.py`, `frontend/components/dashboard/ConnectionBadge.tsx`)와 모델 가중치(`vision/yolov8n.pt`)는
교사가 미리 완성해서 저장소에 올려둔 것이라 별도 설치 과정이 필요 없습니다.
`AGENTS.md`를 열어 팀 주제와 팀원(김다온, 김재민, 김하준, 윤상훈, 이도건, 서종혁)이
이미 채워져 있는지도 확인합니다.

### 0-2. Antigravity로 열기
Antigravity IDE에서 방금 받은 폴더를 워크스페이스로 엽니다.

### 0-3. 하네스 구축 프롬프트 — 프로젝트 뼈대 완성
스타터 킷에 기본 구조가 준비되어 있습니다. Next.js 프론트엔드 스캐폴드와 백엔드 가상환경을 준비합니다.
> 💡 **참고**: Windows PowerShell에서 `pip freeze`를 할 때는 인코딩 충돌을 방지하기 위해 항상 UTF-8로 저장합니다:
> `pip freeze | Out-File -Encoding utf8 requirements.txt`

Antigravity 채팅창에 아래 프롬프트를 입력해 스캐폴드를 완성합니다:

```
이 프로젝트에는 이미 AGENTS.md, .agents/ 하네스, 그리고 기본 보일러플레이트(backend/iot/base.py, backend/websocket_manager.py, vision/yolov8n.pt 등)가 준비되어 있어. 
AGENTS.md의 기술 스택과 폴더 구조를 참고해서 아래를 완성해줘.

1. frontend/ — Next.js(TypeScript, Tailwind) 프로젝트 스캐폴드 (.env.example 충돌 없이 생성)
2. backend/ — Python venv를 활성화하고 requirements.txt(fastapi, uvicorn[standard], websockets, pymysql, sqlalchemy, alembic, python-dotenv, httpx 포함)의 패키지를 설치해줘
3. .gitignore — venv/, __pycache__/, *.pyc, .env, .env.local, node_modules/, .next/ 를 포함해줘
4. 각 폴더의 .env.example을 확인하고 누락된 항목이 없도록 정리해줘

AGENTS.md, .agents/, docs/ 폴더 및 사전 탑재된 유틸리티 파일은 이미 완성되어 있으니 절대 임의로 삭제하거나 덮어쓰지 마 (karpathy-principles.md의 "외과적 변경" 원칙).
```

**확인**: `frontend/`, `backend/`(안에 `venv/`, `requirements.txt`), `vision/`,
`pi/`, `.gitignore`, 그리고 4개의 `.env.example`이 생겼는지 확인합니다.

### Antigravity 인식 확인
Antigravity IDE에서 이 폴더를 워크스페이스로 엽니다. 상단 "…" 메뉴 → **Customizations** 패널에서
Rules/Skills/Workflows 목록에 방금 설치된 항목들이 보이는지 확인합니다. 안 보이면 워크스페이스를
닫았다가 다시 엽니다. Skills 목록에 `attendance-tracking-integration`이 보이고,
`vision-recognition-integration`을 열었을 때 "얼굴 인식(InsightFace)" 절이 들어있으면
이 팀 전용 확장이 정상적으로 인식된 것입니다.

**⚠️ Rules는 3개만 "Always On"으로 설정하세요.** Customizations → Rules에서 아래
3개만 **Always On**으로 켭니다.
- `karpathy-principles` (모든 작업의 기본 전제)
- `security-rules`
- `coding-standards`

나머지 규칙(`api-rules`, `db-rules`, `hardware-rules`, `vision-rules`, `git-rules`,
`deploy-rules`, `ui-ux-rules`)은 Always On으로 켜지 않아도 됩니다 — 각 `agent.md`의
"항상 참고" 항목에 이미 연결돼 있어서, 해당 역할(예: db-agent)을 부를 때 AI가
자동으로 읽습니다. 10개를 전부 Always On으로 켜면 채팅마다 안 쓰는 규칙까지
매번 8,000~12,000 토큰을 소모하므로, 딱 이 3개만 켜는 것이 무료 티어 유지의 핵심입니다.

## 2단계 (1주차). Mock 백엔드 + DB + 대시보드 베이스라인

> 🖥️ **동시 실행 멀티 터미널 안내**:
> IoT 시스템은 여러 프로세스가 실시간으로 통신합니다. **터미널을 3개 열어 각각 실행 상태를 유지**해야 합니다:
> - **터미널 1**: 백엔드 API & WebSocket (`uvicorn main:app --reload --port 8000`)
> - **터미널 2**: Next.js 화면 (`npm run dev`)
> - **터미널 3**: 비전 인식 클라이언트 (`python vision/main.py` — 3단계에서 실행, 이 팀은 카메라 2대를 함께 처리)

```
┌─────────────────────────┐   WebSocket / REST    ┌─────────────────────────┐
│  터미널 1: 백엔드 (8000)  │ ◄──────────────────► │ 터미널 2: 프론트엔드(3000) │
└─────────────────────────┘                       └─────────────────────────┘
             ▲
             │ POST /api/recognition (출입/좌석 인식 결과)
┌─────────────────────────┐
│  터미널 3: 비전 클라이언트 │
│  (출입 카메라 + 교실 카메라)│
└─────────────────────────┘
```

## 3단계 (2주차). 영상인식(얼굴 식별 + 좌석 판정) → 출결 트리거

이 팀은 카메라 2대가 모두 Windows PC에서 돌아서(킷의 기본 가정과 일치) 기본
흐름은 킷과 비슷하지만, **얼굴 식별**(누구인지 특정)과 **좌석 3초 체류 판정**이라는
두 가지가 새로 추가됩니다.

### 3-1. 얼굴 인식 사전 설치 확인 (필수 — 학내망 부하 방지)

## 4단계 (3주차). 하드웨어 마이그레이션 (Mock → 라즈베리파이 5)

`.agents/workflows/hardware-swap.md`를 기본으로 따르되, 이 팀은 액추에이터가
6개(자동문, LED 3색, 네오픽셀, 부저, 릴레이)로 다른 팀보다 많습니다.

> 💡 이 단계를 완료한 뒤부터 하드웨어 관련 개발(서종혁·김하준)을 백엔드·DB
> 담당(김다온)과 나눠서 진행할 때, 서로의 코드를 매번 확인하지 않고도 협업할 수
> 있도록 **`docs/백엔드-라즈베리파이5-연동-인터페이스-가이드.md`**도 함께
> 참고합니다.

```
너는 이 프로젝트의 hardware-agent다. .agents/rules/hardware-rules.md와
.agents/skills/hardware-integration/SKILL.md를 따른다.

backend/iot/base.py의 DeviceProvider 인터페이스를 준수하는 HardwareDeviceProvider로
자동문(MG90S 서보, GPIO18), 상태 LED 3색(GPIO5/6/13), 부저(GPIO17), 릴레이(GPIO22),
리드스위치(GPIO27, 입력), 불꽃 센서(GPIO23, 입력), I2C 온습도 센서(GPIO2/3)를
gpiozero로 제어해줘. 네오픽셀 LED 스트립(GPIO10)만 gpiozero로 직접 제어하기
어려우니 별도 라이브러리(rpi_ws281x 또는 adafruit-circuitpython-neopixel)로
따로 만들어줘.
```

### 라즈베리파이 쪽 준비 (직접 실행)
라즈베리파이 5는 `gpiozero` 외에 RP1 칩 제어를 위한 `lgpio`가 필수이고, 네오픽셀
제어를 위한 별도 라이브러리도 필요합니다. 파이 터미널에서:
```bash
cd pi
python3 -m venv venv
source venv/bin/activate
pip install gpiozero lgpio requests python-dotenv
# 네오픽셀 라이브러리 (팀이 고른 쪽으로 택 1)
pip install rpi_ws281x adafruit-circuitpython-neopixel
```
> ⚠️ 네오픽셀 라이브러리는 보통 하드웨어 타이밍 제어를 위해 **관리자 권한(sudo)**이
> 필요합니다. `sudo python3 main.py`로 실행해야 할 수 있다는 점을 배선 전에
> 확인합니다.

Windows PC의 IP를 확인하여 파이에 알려줍니다:
```powershell
ipconfig
# IPv4 주소 확인 (예: 192.168.0.25)
```
그 값을 `pi/.env`의 `BACKEND_URL`에 적습니다:
```
BACKEND_URL=http://192.168.0.25:8000
```

배선은 **전원을 끈 상태**에서, **교사 입회 하**에 연결합니다. 특히 이 팀은
릴레이·서보·네오픽셀에 5V 외부 전원과 4채널 레벨컨버터가 필요하므로(PRD 8.1),
배선도를 다시 한번 확인한 뒤 전원을 넣습니다. 연결 후:
```powershell
# backend/.env
DEVICE_MODE=hardware
```
**확인**: 얼굴 인증 성공 시 실제 자동문이 열리고 5초 후 닫히는지, 좌석 LED/
네오픽셀이 상태에 맞게 반응하는지, 재실 인원 변화에 따라 조명이 켜지고 꺼지는지
확인합니다.

## 막혔을 때 (FAQ & 트러블슈팅)

| 상황 / 에러 메시지 | 해결 방법 |
|---|---|
| `ModuleNotFoundError: No module named 'backend'` | `backend/main.py` 최상단에 `sys.path` 주입 코드가 포함되어 있는지 확인하거나, `cd backend` 경로에서 `uvicorn main:app`을 실행합니다. |
| `pip freeze` 후 `unsupported mime type charset=utf-16le` 에러 | PowerShell의 기본 리다이렉션 대신 `pip freeze \| Out-File -Encoding utf8 requirements.txt` 명령을 사용합니다. |
| `RuntimeError: The starlette.testclient module requires the httpx package` | 백엔드 가상환경에서 `pip install httpx`를 실행합니다 (`backend/requirements.txt`에 포함됨). |
| Next.js 화면 `Hydration failed` 경고 | 시간 렌더링 태그에 `suppressHydrationWarning` 속성을 추가하거나 `components/dashboard/ConnectionBadge.tsx`를 사용합니다. |
| `Control request failed: Failed to fetch` | 백엔드 서버(터미널 1: `http://localhost:8000`)가 켜져 있는지 확인합니다. |
| 웹캠 화면이 검은색으로 나오거나 멈춤 | Zoom, Teams, 브라우저 등 웹캠을 점유 중인 다른 프로그램을 모두 작업 관리자에서 종료합니다. |
| `Activate.ps1` 실행 불가 (`PSSecurityException`) | PowerShell에서 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` 실행 후 다시 활성화합니다. |
| `mysql: command not found` | `C:\xampp\mysql\bin\mysql.exe -u root`로 직접 지정하거나 phpMyAdmin 웹 UI SQL 탭에 붙여넣어 실행합니다. |
| `pip install insightface` 실패 또는 매우 오래 걸림 | Python 3.12 venv인지 먼저 확인합니다. 그래도 실패하면 `onnxruntime`을 먼저 단독 설치한 뒤 `insightface`를 다시 설치해봅니다. 팀 전체가 동시에 설치하지 말고 1명이 먼저 검증하세요(학내망 부하 방지). |
| 카메라 2대 중 하나만 열림 (`cv2.VideoCapture` 실패) | `ENTRY_CAMERA_INDEX`/`CLASSROOM_CAMERA_INDEX` 값이 실제 장치 번호와 맞는지 Windows 카메라 앱에서 먼저 확인합니다. USB 포트를 바꾸면 인덱스가 바뀔 수 있습니다. |
| 좌석 판정이 계속 `MISMATCH`로 나옴 | 좌석 ROI 좌표가 실제 카메라 화면과 맞는지 확인합니다. 기구물·카메라 위치가 확정되기 전(3단계)에는 대략적인 좌표로 테스트하고, 4단계 기구물 완성 후 다시 보정합니다. |
| 라즈베리파이에서 네오픽셀이 반응 없음 | `sudo python3 main.py`로 관리자 권한 실행이 필요한지 확인하고, GPIO10(SPI) 배선과 4채널 레벨컨버터 연결을 다시 확인합니다. |
