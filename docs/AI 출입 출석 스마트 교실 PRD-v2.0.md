1. 얼굴 인식 기반 학생·교사 입실, 퇴실, 재입실 처리

3. 교사·관리자 화면의 출석, 좌석, 재실 인원 및 경고 실시간 확인
4. 등록 승인, 교실·스케줄·로그 관리
5. Raspberry Pi 5 기반 자동문, 좌석·상태 LED, 부저, 릴레이 제어
6. 불꽃·온습도 센서 기반 교실 안전·환경 상태 표시

# 2. 문제와 목표

## 2.1 해결하려는 문제

- 출석 인증 뒤 실제 수업 참여 여부를 확인하기 어렵다.
- 대리 출석, 무단 이탈, 실제 착석 여부를 기존 방식으로는 효과적으로 확인하기 어렵다.
- 교사가 출석과 학생 상태를 직접 관리해야 한다.

## 2.2 프로젝트 목표

### 기능 목표

- 얼굴 인식으로 학생과 교사의 입실·퇴실·재입실을 관리한다.
- 학생이 선택한 좌석과 실제 검출 좌석을 비교해 출석·착석 상태를 관리한다.
- 교사가 출석 현황, 학생 상태, 좌석 현황을 확인하고 학생 상태를 변경할 수 있게 한다.
- 관리자가 신규 등록, 교실, 스케줄, 출입·경고 로그를 관리하게 한다.

### 기술 목표

- Windows PC에서 FastAPI(Python VENV), MySQL, Next.js(TypeScript)를 실행한다.
- OpenCV, InsightFace, YOLO를 사용해 얼굴 인식과 사람 검출을 처리한다.
- WebSocket(JSON)으로 출석·좌석·학생 상태·재실 인원·경고를 실시간 동기화한다.
- Raspberry Pi 5(Trixie OS)에서 gpiozero를 우선 사용해 하드웨어를 제어한다.
- 신청된 FHD 웹캠 2대, MG90S 서보모터, 리드스위치, LED·네오픽셀, 불꽃·온습도 센서를 실제 시연 장치에 연결한다.

## 3.1 사용자

- 학생: 입실, 퇴실, 재입실, 얼굴 등록 요청
- 교사: 입실, 퇴실, 출석 현황 조회, 학생 상태 변경
- 관리자: 신규 등록 승인, 교실·스케줄 관리, 출입·경고 로그 조회

학생의 실제 착석과 재실을 기존 출석 방식만으로 확인하기 어렵고, 교사는 수동 출석 관리 부담을 가진다.

## 4.1 기능별 상세 요구사항

### F-01 얼굴 기반 출입 인증

- 목적: 등록된 학생·교사의 입실, 퇴실, 재입실을 식별한다.
- 입력: 출입 카메라 프레임, 사용자 유형·동작 선택, 교실 정보.
- 처리: OpenCV로 얼굴을 검출하고 InsightFace 임베딩을 저장 벡터와 비교한다.
- 출력: 인증 결과, 사용자, 출입 처리 결과, 위치 상태.
- 정상 동작: 인증 성공 시 정해진 입실/퇴실/재입실 시나리오의 상태를 저장하고 화면을 갱신한다.
- 예외 상황: 얼굴 인식 실패 시 실패 로그를 저장하고 5회 실패 시 경고 로그·부저·관리자 경고를 발생시킨다.
- 완료 조건: 학생과 교사의 입실·퇴실·재입실 시나리오가 DB와 화면에서 일치한다.

### F-02 좌석 기반 출석

- 목적: 인증만으로 끝나지 않고 실제 선택 좌석 착석을 확인한다.
- 입력: 학생이 선택한 좌석, 교실 카메라 프레임, 좌석별 사전 정의 ROI.
- 처리: YOLO로 사람을 검출하고 InsightFace로 학생을 식별한다. 동일 학생이 선택 좌석 ROI에 3초 이상 검출되면 OCCUPIED로 처리한다.
- 출력: RESERVED, OCCUPIED, MISMATCH, EMPTY 중 좌석 상태와 출석·위치 상태.
- 정상 동작: 동일 학생이 선택 좌석에서 확인되면 PRESENT, IN_CLASS, OCCUPIED로 저장한다.
- 예외 상황: 선택 ROI와 실제 ROI가 다르면 MISMATCH, 경고 로그, 교사 경고를 생성한다. 시스템은 좌석을 자동 변경하지 않으며 최종 판단은 교사가 한다.
- 완료 조건: 6석 각각에서 정상 착석, 빈 좌석, 좌석 불일치가 구분된다.

### F-03 교사 출석 관리

- 목적: 교사가 수업 중 출석과 학생 상태를 확인·변경한다.
- 입력: 교사 화면 요청, 학생 상태 변경 요청.
- 처리: 현재 교실의 출석·좌석·재실 데이터를 조회하거나 상태를 수정한다.
- 출력: 총원, 출석·결석·지각 인원, 학생 이름·좌석 번호·좌석 상태.
- 정상 동작: 화장실, 양호실, 조퇴, 결석 상태 변경이 저장·실시간 반영된다.
- 예외 상황: 교사·관리자 권한이 아닌 요청은 HTTP 403, 존재하지 않는 학생은 HTTP 404, 형식 오류는 HTTP 422로 응답한다. `[권장]`
- 완료 조건: 교사 화면에서 계획서에 명시된 조회·상태 변경이 가능하다.

### F-04 관리자 관리

- 목적: 사용자 등록과 교실·스케줄·로그를 관리한다.
- 입력: 등록 요청, 교실·스케줄·학생 배정, 조회 조건.
- 처리: 등록 승인 후 얼굴 특징 벡터를 저장하고 사용 가능 상태로 전환한다. 관리 데이터의 생성·수정·삭제를 처리한다.
- 출력: 승인 결과, 관리 목록, 출입·얼굴인식 실패·경고 로그.
- 정상 동작: 승인된 사용자만 시스템에서 사용할 수 있다.
- 예외 상황: 등록 거부 시 `reason` 문자열을 필수로 저장하고 요청 상태를 REJECTED로 변경한다. `[권장]`
- 완료 조건: 신규 등록 승인과 계획서에 명시된 관리 기능을 시연한다.

### F-05 실시간 동기화

- 목적: 교사·관리자 화면의 상태를 지연 없이 같은 데이터로 유지한다.
- 입력: 출입·좌석·학생 상태·재실·경고 이벤트.
- 처리: FastAPI가 WebSocket(JSON) 이벤트를 연결된 화면에 전달한다.
- 출력: 화면의 실시간 상태 갱신.
- 정상 동작: 이벤트 발생 뒤 관련 화면이 갱신된다.
- 예외 상황: 연결 끊김 시 재연결 후 DB 상태를 기준으로 재동기화한다.
- 완료 조건: 입실, 좌석 불일치, 퇴실, 경고를 두 화면에서 확인한다.

### F-06 하드웨어 제어

- 목적: 미니어처 교실에서 출석·경고 상태를 물리적으로 보여 준다.
- 입력: 입실 선택 좌석, 얼굴 인식 실패 횟수, 교실 재실 인원, 센서 상태.
- 처리: Raspberry Pi가 개별 LED·네오픽셀, 부저, 릴레이를 제어한다.
- 출력: 선택 좌석 LED 점멸, 5회 실패 시 부저, 재실 인원 변화 시 조명 릴레이 ON/OFF, 상태 LED·네오픽셀 표시.
- 정상 동작: 0명→1명 이상이면 조명 ON, 1명 이상→0명이면 조명 OFF.
- 예외 상황: 서보·릴레이·네오픽셀은 별도 5V 어댑터로 공급하고 Raspberry Pi와 공통 접지를 사용한다. 4채널 레벨컨버터로 3.3V/5V 신호를 변환한다.
- 완료 조건: 위 세 가지 이벤트와 하드웨어 동작을 시연한다.

### F-07 자동문·안전 상태 제어

- 목적: 출입 인증 성공 시 미니어처 자동문을 열고, 문 상태와 교실 안전·환경 센서 값을 확인한다.
- 입력: 인증 성공 이벤트, 리드스위치 문 열림/닫힘 신호, 불꽃 감지 신호, 온습도 I2C 값.
- 처리: MG90S 서보모터로 문을 열고 5초 뒤 닫는다. 리드스위치로 닫힘 상태를 확인한다. 불꽃 감지 시 경고를 발생시키고, 온습도는 화면에 표시한다.
- 출력: 문 OPEN/CLOSED 상태, 안전 경고, 온도·습도 값.
- 정상 동작: 인증 성공 시 문 OPEN, 5초 후 CLOSED이며 리드스위치 상태와 일치한다.
- 예외 상황: 문 상태가 명령과 다르면 하드웨어 경고 로그를 저장한다. 온습도 센서의 정확한 모델별 측정 범위는 부품 수령 후 검증한다.
- 완료 조건: 자동문 개방·닫힘, 리드스위치 확인, 불꽃 감지 경고, 온습도 화면 표시를 시연한다.

## 8.1 액추에이터 상세

### A-01 좌석 LED

- 목적: 학생 입실 시 선택한 좌석을 안내한다.
- GPIO: GPIO 5(파랑), GPIO 6(빨강), GPIO 13(초록)으로 시연 상태 LED를 구성한다.
- 제어 방법: gpiozero의 LED 제어를 우선 사용하며, 좌석 수가 6석이므로 네오픽셀 스트립을 좌석별 안내 표시로 사용한다.
- 입력 명령: 선택 좌석 RESERVED 이벤트.
- 동작 상태: 선택 좌석 LED 점멸.
- 안전 조건: 개별 5mm LED에는 전류 제한 저항을 사용하고, 네오픽셀 5V 전원은 Raspberry Pi GPIO 전원과 분리한다.

### A-02 부저

- 목적: 얼굴 인식 실패 5회 시 경고음을 낸다.
- GPIO: GPIO 17.
- 제어 방법: gpiozero를 우선 사용.
- 입력 명령: 5회 실패 경고 이벤트.
- 동작 상태: OFF / 경고음.
- 안전 조건: 3~7V TMB12A05 부저의 정격 전원과 GPIO 구동 방식을 배선 전 확인한다.

### A-03 릴레이

- 목적: 재실 인원에 따라 교실 조명을 제어한다.
- GPIO: GPIO 22.
- 제어 방법: gpiozero의 출력 장치 제어를 우선 사용.
- 입력 명령: 재실 인원 0→1 이상, 1 이상→0 이벤트.
- 동작 상태: 조명 OFF / ON.
- 안전 조건: 5V 1채널 릴레이 모듈은 5V 외부 전원을 사용하고, GPIO 22 신호는 4채널 레벨컨버터를 거쳐 입력한다. Raspberry Pi와 공통 접지를 구성하며, 실제 AC 부하는 연결하지 않고 미니어처 DC 조명만 제어한다.

### A-04 MG90S 서보모터 자동문

- 목적: 얼굴 인증 성공 시 미니어처 출입문을 개방한다.
- GPIO: GPIO 18(PWM).
- 제어 방법: `gpiozero.AngularServo`를 우선 사용한다.
- 입력 명령: 인증 성공 시 OPEN, 5초 뒤 CLOSED.
- 동작 상태: OPEN / CLOSED.
- 안전 조건: 서보모터 5V 전원은 Raspberry Pi와 분리하고 공통 접지를 사용한다. 문이 걸리거나 과도한 토크가 발생하지 않도록 가벼운 아크릴·포맥스 문을 사용한다.

### A-05 네오픽셀 LED 스트립

- 목적: 6개 좌석의 선택·착석·불일치 상태와 안전 상태를 색으로 표시한다.
- GPIO: GPIO 10(SPI MOSI) 출력, 4채널 레벨컨버터를 통해 5V 데이터 신호로 변환.
- 제어 방법: NeoPixel 호환 Python 라이브러리 사용. gpiozero로 직접 제어하기 어려운 장치이므로 예외로 별도 라이브러리를 사용한다. `[권장]`
- 입력 명령: RESERVED=파랑 점멸, OCCUPIED=초록 점등, MISMATCH=빨강 점멸, 안전 경고=빨강 점멸.
- 동작 상태: OFF / 색상 / 점멸.
- 안전 조건: 5V 어댑터와 DC 전원 잭 어댑터로 전원을 공급하고, 전원 투입 전 전류 용량을 확인한다.

6석 미니어처 교실, 학생 피규어와 얼굴 이미지, MG90S 자동문과 리드스위치, 네오픽셀 좌석 표시부, FHD 출입·교실 웹캠 설치부, Raspberry Pi 5와 릴레이·부저·불꽃·온습도 센서 설치부를 제작한다.

## 10.2 사용 재료

| 재료 | 사용 위치 | 목적 |
|---|---|---|
| 알루미늄 프로파일 | 교실 외곽 프레임 | 기구물 강성 확보 |
| 아크릴 | 자동문과 카메라 고정판 | 문 개폐와 카메라 위치 고정 |
| 포맥스 | 좌석판·벽면·배선 덮개 | 좌석 구획과 부품 보호 |
| 우드락 | 교실 바닥·배경판 | 가벼운 미니어처 바닥·배경 구성 |
| 기타 | 5V 어댑터, DC 전원 잭 어댑터, 4채널 레벨컨버터 | 서보·릴레이·네오픽셀 전원 및 3.3V/5V 신호 변환 |

## 10.3 기구 설계 요구사항

- 기구물은 6석·카메라 2대·자동문이 한 화면에 들어오는 탁상형 미니어처로 제작한다. 정확한 가로·세로·높이와 무게는 재료 수급 후 도면에서 확정한다.
- 출입 카메라는 얼굴 인증이 가능하도록 출입 위치에, 교실 카메라는 6개 좌석 ROI를 모두 볼 수 있는 위치에 설치한다.
- LED·카메라·배선이 학생 피규어 및 좌석 이동에 간섭하지 않아야 한다.
- 서보·릴레이·전원부는 교실 하부 또는 후면에 고정하고, 5V 전원선과 GPIO 신호선을 분리 정리한다. 고전압 AC 전원은 사용하지 않는다.

# 21. MVP

## 21.1 MVP 1 - 핵심 출석 시연

### 목표

등록된 학생이 얼굴 인증과 좌석 확인을 거쳐 출석 처리되고, 교사 화면에서 결과를 확인한다.

### Hardware MVP 1

- 6석 미니어처 교실 기본 기구물 제작
    
- Raspberry Pi 5에서 gpiozero로 좌석 LED 또는 네오픽셀 상태 표시
    
- 출입 웹캠 1대와 교실 웹캠 1대 연결
    
- GPIO 번호·전원·배선 확인
    

### Backend MVP 1

- FastAPI와 Python VENV 실행
    
- MySQL 연결
    
- 사용자, 좌석, 출석, 출입 로그 저장·조회
    
- 얼굴 인증 결과를 출석 상태로 처리
    
- 선택 좌석과 실제 좌석 ROI를 비교하여 RESERVED, OCCUPIED, MISMATCH 처리
    
- REST API(JSON)로 사용자·좌석·출석 현황 조회
    
- WebSocket(JSON)으로 좌석·출석 상태 갱신
    

### Frontend MVP 1

- 학생 입실 화면: 교실 선택, 좌석 선택, 얼굴 인증 결과 표시
    
- 교사 화면: 출석 인원, 좌석 상태, 재실 인원 표시
    
- 좌석 불일치와 얼굴 인식 실패 상태 표시
    
- WebSocket 실시간 상태 반영
    

### 통합 MVP 1 완료 기준

```
출입 카메라 → 얼굴 인증 → FastAPI → MySQL
→ 좌석 선택 → 교실 카메라 ROI 확인
→ PRESENT / OCCUPIED 또는 MISMATCH
→ 교사 화면 WebSocket 갱신
→ 선택 좌석 LED·네오픽셀 표시
```

# 24. 보안

- 관리자 인증은 JWT, 비밀번호는 bcrypt 해시 저장을 사용한다.
- CORS는 FastAPI에서 Frontend 통신이 가능하도록 설정한다.
- ORM을 사용해 SQL Injection 위험을 줄인다.
- `.env`에 DB 비밀번호와 민감정보를 저장하고 Git에 커밋하지 않는다.
- 학번, 이름, 사용자 역할, 얼굴 특징 벡터, 출입·출석·좌석 배정 정보만 저장한다.
- 원본 얼굴 이미지, 원본 카메라 영상, 원본 프레임 데이터는 저장하지 않는다.

## 30.1 계획서에서 누락된 내용

- 없음. 계획서의 핵심 기능, 센서·액추에이터, 시스템 구성, 팀원 역할은 본 PRD에 반영했다.

## 30.2 PRD에 추가된 내용

- `[권장]` Backend 폴더 분리, API 오류 응답 문서화, FastAPI 자동 문서 활용, 실제 하드웨어 전 Python 시뮬레이터 테스트는 학생 구현·테스트를 위한 제안이다.
- 자동문·리드스위치·불꽃·온습도·네오픽셀 기능과 FHD 웹캠 규격은 신청서의 실제 선정 부품을 반영해 추가했다.
- API Endpoint, DB 테이블명, 8주 일정, JWT/bcrypt, CORS, 원본 영상 미저장 등은 입력된 기존 PRD v2.0 또는 프로젝트 개발 계획서에 근거한다.

## 30.3 결정되지 않은 사항

1. 팀명, 팀원 실명, 역할별 산출물
2. 얼굴 유사도 임계값, 인식률·응답시간 목표값, 실제 조명 환경 기준
3. 기구물의 정확한 치수·무게·조립·운반 방법
4. 온습도 센서의 정확한 모델과 교실 환경 기준값

# 31. 최종 PRD 요약

## 프로젝트

AI 출입 출석 스마트 교실

## 핵심 문제

기존 출석은 실제 착석·재실·무단 이탈을 충분히 확인하기 어렵다.

## 해결 방법

얼굴 인증과 교실 카메라의 좌석 ROI 판정을 결합하고, 교사·관리자 화면과 Raspberry Pi 하드웨어로 상태를 실시간 관리한다.

## 핵심 센서

출입 카메라, 교실 카메라

## 핵심 액추에이터

MG90S 자동문, 좌석 LED·네오픽셀, 부저, 릴레이(교실 조명)

## 핵심 Backend

FastAPI + MySQL

## 핵심 Frontend

Next.js(TypeScript)

## Hardware

Raspberry Pi 5(Trixie OS + gpiozero 우선)

## 핵심 데이터 흐름

```text
FHD 웹캠·리드스위치·불꽃·온습도 → 영상인식/Raspberry Pi 5 → FastAPI → MySQL → Next.js
이벤트 → FastAPI → Raspberry Pi 5 → 자동문 / LED / 네오픽셀 / 부저 / 릴레이
```

## MVP

학생의 얼굴 인증과 좌석 확인으로 출석을 처리하고, 자동문·문 상태·안전·환경 상태를 교사·관리자 화면에 실시간 표시하는 단일 교실 6석 시연.

## 최종 완성 목표

입실, 출석, 좌석 검증, 퇴실, 재입실, 무단 이탈 감지, 교사 모니터링, 관리자 관리를 하나의 미니어처 스마트 교실에서 시연한다.

# 32. 생성형 AI용 PRD 작성 지침

## 입력 자료

1. 프로젝트 개발 계획서
2. PRD 공통 양식
3. 팀별 PRD-v2.0.md

## 우선순위

```text
프로젝트 개발 계획서
↓
공통 개발환경
↓
PRD 공통 양식
↓
기존 PRD v2.0의 계획서와 충돌하지 않는 내용
↓
AI의 [권장] 사항
```

## 반드시 지킬 것

- 계획서의 주제·목표·기능·팀원 역할을 최우선으로 반영한다.
- 결정되지 않은 내용은 `[미정]`, AI 제안은 `[권장]`으로 표시한다.
- Windows OS PC, FastAPI + Python VENV, MySQL, Next.js + TypeScript, Raspberry Pi 5 + Trixie OS, gpiozero 우선 환경을 사용한다.
- 계획서에 없는 기능을 확정 요구사항으로 추가하지 않는다.
- 관련 없는 항목은 `해당 없음`으로 표시한다.
