## 1. 프로젝트 개요 및 1차 완성 현황

### 1.1 팀 주제 및 한 줄 목표
- **주제**: `얼굴 인식과 교실 카메라를 이용해 출입, 출석, 좌석, 재실 상태를 통합 관리하는 스마트 교실`
- **목표**: 얼굴 인식과 좌석·교실 카메라 판정을 연결하여 학생의 출입, 출석, 착석 및 재실 상태를 교사와 관리자가 실시간으로 확인하고 IoT 액추에이터를 자동 제어하는 스마트 교실 구현.

### 1.2 시스템 디바이스 10종 정의 (시드 등록 완료)
| 구분 | 디바이스 ID | 이름 | Kind | 제어/측정 방식 | 1차 시스템 동작 방식 |
|---|---|---|---|---|---|
| **액추에이터** | `servo_door` | MG90S 서보모터(자동문) | `servo` | PWM (각도 제어) | `OPEN(90°)` 명령 시 5초 후 자동으로 `CLOSED(0°)` 복귀 |
| **액추에이터** | `seat_led` | 좌석 LED | `led` | GPIO (ON/OFF/점멸) | 입실 시 선택 좌석 안내 점등 |
| **액추에이터** | `neopixel_seat` | 네오픽셀 | `neopixel` | SPI (색상/모드) | 좌석 상태(초록: 착석, 파랑: 예약, 빨강: 불일치) 표시 |
| **액추에이터** | `buzzer` | 부저 | `buzzer` | GPIO (주파수/소리) | 인증 실패 시 경고음 울림 (2초 후 자동 정지) |
| **액추에이터** | `relay_light` | 릴레이(교실 조명) | `relay` | GPIO (ON/OFF) | 재실 인원 1명 이상 시 자동 ON, 0명이면 OFF |
| **센서** | `cam_entrance` | FHD 출입 웹캠 | `camera` | USB 웹캠 | 출입 인증용 영상 스트림 (상태 모니터링) |
| **센서** | `cam_classroom` | FHD 교실 웹캠 | `camera` | USB 웹캠 | 교실 전경 및 6석 ROI 착석 감지 |
| **센서** | `reed_switch` | 리드스위치 | `reed_switch` | GPIO 디지털 입력 | 자동문 개폐 상태 연동 감지 (열림: 0, 닫힘: 1) |
| **센서** | `flame_sensor` | 불꽃 센서 | `flame_sensor` | GPIO 디지털 입력 | 화재 감지 시 경보 발생 (대시보드 수동 해제 전까지 유지) |
| **센서** | `dht_sensor` | 온습도 센서 | `dht11` | I2C 디지털 통신 | Random Walk 알고리즘으로 자연스러운 실시간 변화 시뮬레이션 |

## 3. 1차 시스템 실행 및 동작 테스트 방법

### 3.1 멀티 터미널 실행 명령어
총 3개의 터미널에서 아래 명령을 실행합니다:

```powershell
# [터미널 1] 백엔드 구동
cd backend
.\venv\Scripts\Activate.ps1
uvicorn main:app --reload --port 8000
```
- 확인: 브라우저에서 `http://localhost:8000/docs` (Swagger) 접속 확인

```powershell
# [터미널 2] 프론트엔드 대시보드 구동
cd frontend
npm run dev
```
- 확인: 브라우저에서 `http://localhost:3000` 접속 (우측 상단 `● 실시간 연결됨` 초록색 배지 확인)

```powershell
# [터미널 3] 비전 클라이언트 구동
cd vision
.\venv\Scripts\Activate.ps1
python main.py
```
- 확인: `Smart Classroom Vision Client` OpenCV 창이 뜨며 6개 좌석 ROI 박스가 렌더링됨

### 3.2 핵심 시나리오 테스트 단축키
비전 창을 마우스로 클릭하여 활성화한 후 단축키를 입력합니다:
1. **`E` (입실 인증)**: 콘솔에 `face_recognized` 전송 → 서보문 OPEN(90°) → 릴레이 조명 ON → 출석부에 `김재민 출석완료` 기록 → **5초 뒤 서보문 자동 CLOSED(0°)** 및 리드스위치 닫힘 원복
2. **`U` (인증 실패)**: `face_unrecognized` 전송 → 부저 경고음 작동 (2초 후 자동 정지)
3. **`1`~`6` (좌석 판정)**: 대시보드에서 좌석 배정 후 해당 좌석 번호 키 입력 → `정상 착석(초록)` ↔ `불일치 경고(빨강 깜빡임)` ↔ `빈 좌석` 상태 순환
4. **`F` (화재 경보)**: `flame_detected` 전송 → 대시보드 상단 빨간색 화재 경보 펄스 발동 → 대시보드의 **`[경보 수동 해제]`** 버튼을 눌러야만 해제됨
5. **`Q`**: 비전 클라이언트 정상 종료

## 4. 기존 기능 수정 및 보완 방법 (Fine-tuning)

학생들이 시스템 파라미터를 변경하고자 할 때 수정해야 하는 위치입니다:

### 4.1 자동문 개폐 각도 및 닫힘 대기 시간 변경
- **수정 파일**: `backend/iot/mock_provider.py`
  - `set_actuator_state` 내부: 서보모터 열림 각도 `{"angle": 90}`를 원하는 각도로 변경
  - `_auto_close_door_after_delay(5.0)`: 5초 대신 원하는 초 단위 시간(예: `3.0` 또는 `10.0`)으로 변경

### 4.2 학생 명단 및 좌석 수 변경
- **수정 파일**: `backend/routes/classroom.py`
  - `REGISTERED_STUDENTS`: 학번-이름 딕셔너리 수정
  - `ATTENDANCE_LOG`: 초기 출석부 리스트 수정
  - `SEATS`: 좌석 수 확장 시 7, 8번 추가
- **비전 ROI 수정**: `vision/main.py`의 `seat_rois` 좌표 딕셔너리 수정

### 4.3 온습도 Random Walk 범위 수정
- **수정 파일**: `backend/iot/mock_provider.py`
  - `read_sensor_value("dht_sensor")` 내의 기본 온도(23.5°C), 습도(52.0%) 및 난수 변동 폭 수정

### 4.4 PyTorch DLL([WinError 1114]) 해결 방법
- 원인: Windows 시스템에 Visual C++ 재배포 패키지가 없거나 파이썬 3.14 호환 이슈
- 해결: [Microsoft Visual C++ 2015-2022 재배포 가능 패키지(x64)](https://aka.ms/vs/17/release/vc_redist.x64.exe) 설치

## 5. 신규 기능 및 디바이스 추가 방법

새로운 센서나 액추에이터를 추가할 때는 `.agents/skills/iot-endpoint-generator/SKILL.md`의 **4단계 원칙**을 따릅니다:

1. **1단계 (DB)**: `backend/db/init.sql`의 디바이스 시드에 신규 디바이스 추가
   ```sql
   INSERT INTO devices (id, name, kind) VALUES ('new_sensor_1', '새 센서', 'sensor_kind')
   ON DUPLICATE KEY UPDATE name = VALUES(name), kind = VALUES(kind);
   ```
2. **2단계 (Provider)**: `backend/iot/mock_provider.py`의 `_states` 딕셔너리에 기본 상태 등록 및 `set_actuator_state` / `read_sensor_value` 처리 로직 추가
3. **3단계 (API 엔드포인트)**: `backend/routes/devices.py`에 특화 제어가 필요할 경우 라우트 추가
4. **4단계 (프론트엔드 UI)**:
   - `frontend/app/page.tsx`의 `actuators` 또는 `sensors` 배열에 해당 id 매핑
   - `frontend/components/dashboard/statusColor.ts` 색상 규칙 적용

## 6. API 및 통신 인터페이스 규격 (REST & WebSocket)

### 6.1 인증 분리 규칙 (중요)
- **사용자향 (대시보드)**: 일반 호출 허용 (배포 시 Supabase JWT 검증 적용)
- **디바이스향 (비전 클라이언트, 라즈베리파이)**: `X-Device-Api-Key` 헤더 필수 (`backend/.env`의 `DEVICE_API_KEY`와 일치해야 함)

### 6.2 주요 REST 엔드포인트
| 메서드 | 엔드포인트 | 인증 | 설명 |
|---|---|---|---|
| `GET` | `/api/devices` | 없음 | 등록된 전체 디바이스 목록 및 실시간 상태 조회 |
| `POST` | `/api/devices/{id}/control` | 없음 | 액추에이터 제어 (`desired_state`, `desired_value`) |
| `POST` | `/api/devices/{id}/reset-alert` | 없음 | 경보성 디바이스(화재 등) 수동 해제 |
| `GET` | `/api/seats` | 없음 | 6개 좌석 전체 상태 조회 |
| `POST` | `/api/seats/{id}/reserve` | 없음 | 특정 좌석 학생에게 배정/예약 |
| `POST` | `/api/seats/{id}/release` | 없음 | 좌석 퇴실/해제 |
| `GET` | `/api/attendance` | 없음 | 학생 출석부 목록 조회 |
| `POST` | `/api/v1/vision/events` | **API Key** | 비전 감지 이벤트 전송 및 트리거 실행 |
| `GET` | `/api/v1/devices/{id}/desired-state` | **API Key** | 하드웨어(라즈베리파이)가 목표 상태 폴링 |
| `POST` | `/api/v1/devices/{id}/state` | **API Key** | 하드웨어가 실제 반영 상태를 백엔드에 보고 |

### 6.3 WebSocket 브로드캐스트 규격 (`ws://localhost:8000/ws`)
백엔드에서 브로드캐스트하는 메시지 유형:
- `init_state`: 클라이언트 접속 직후 devices, seats, attendance 스냅샷 전송
- `device_update`: 디바이스 상태 변경 시 (`device_id`, `current_state`, `current_value`)
- `seat_update`: 좌석 배정/해제/판정 변경 시
- `vision_event`: 비전 감지 이벤트 수신 및 실행된 트리거 목록 전송
- `sensor_tick`: 3초 주기 온습도 및 센서 실시간 갱신 데이터 전송

## 7. 라즈베리파이 5 하드웨어 마이그레이션 가이드 (2차 핵심)

라즈베리파이 5 실물 연동(2차 완성) 시 학생들이 반드시 수행해야 하는 작업입니다.

### 7.1 구조적 전환 원칙
- **1차 시스템**: `DEVICE_MODE=mock` → `MockDeviceProvider`가 소프트웨어로 시뮬레이션
- **2차 시스템**: `DEVICE_MODE=hardware`
  - 백엔드: `backend/iot/hardware_provider.py`가 desired-state를 DB에 보관하는 **중계 역할**만 수행 (GPIO 직접 제어 X)
  - 라즈베리파이: `pi/main.py`가 백엔드를 1~2초 주기로 폴링하여 실제 GPIO를 제어하고 결과를 보고

### 7.2 라즈베리파이 5 핀맵 기준표 (PRD v2.0 기반)
| 디바이스 | 핀 번호 | 제어 방식 | 라이브러리 객체 |
|---|---|---|---|
| MG90S 서보모터 (자동문) | GPIO 18 | PWM (50Hz) | `gpiozero.AngularServo(18, min_angle=0, max_angle=90)` |
| 리드스위치 (문 닫힘 감지) | GPIO 27 | Digital In (Pull-up) | `gpiozero.DigitalInputDevice(27, pull_up=True)` |
| 불꽃 센서 | GPIO 23 | Digital In | `gpiozero.DigitalInputDevice(23)` (4채널 레벨컨버터 사용) |
| DHT11 / I2C 온습도 | GPIO 2(SDA), 3(SCL) | I2C 통신 | `adafruit-circuitpython-dht` 또는 smbus2 |
| 교실 조명 릴레이 | GPIO 22 | Digital Out | `gpiozero.OutputDevice(22)` (레벨컨버터 거침) |
| 부저 | GPIO 17 | Digital Out / PWM | `gpiozero.Buzzer(17)` |
| 좌석 상태 LED | GPIO 5, 6, 13 | Digital Out | `gpiozero.LED` |
| 네오픽셀 LED 스트립 | GPIO 10 (MOSI) | SPI 통신 | `rpi_ws281x` 라이브러리 |

> ⚠️ **라즈베리파이 5 주의사항**: RP1 칩셋 특성상 반드시 `GPIOZERO_PIN_FACTORY=lgpio` 환경변수를 설정해야 합니다.

### 7.3 네트워크 설정 (PC IP 확인)
라즈베리파이는 다른 기기이므로 `localhost`를 쓸 수 없습니다:
1. Windows PC 터미널에서 `ipconfig` 실행 → IPv4 주소 확인 (예: `192.168.0.25`)
2. `pi/.env` 파일 설정:
   ```ini
   BACKEND_URL=http://192.168.0.25:8000
   DEVICE_API_KEY=CLASS_2026_09_05_v1_0_0
   GPIOZERO_PIN_FACTORY=lgpio
   ```

```text
너는 이 프로젝트의 hardware-agent다.
```

### 프롬프트 ②: [비전 AI 담당자] 실제 얼굴 인식 및 학생 식별 고도화

> 💡 **비전 고도화 구현 시 필수 가이드 (시행착오 방지)**:
> - **라이브러리 주의**: `dlib`, `face_recognition`, `insightface`(소스 빌드)는 Windows에서 C++ 컴파일러(Visual Studio Build Tools) 미설치로 심각한 설치 오류를 유발하므로 **절대 새로 설치하지 않습니다.**
> - **권장 구현 방식**: 이미 `vision/requirements.txt`에 탑재된 **`onnxruntime` (경량 ArcFace/MobileFaceNet ONNX)** 또는 **OpenCV DNN 내장 모델 (`cv2.FaceDetectorYN`, `cv2.FaceRecognizerSF`)** 또는 **`mediapipe`**를 사용합니다.
> - **인식률 및 성능**: 경량 ONNX 방식은 LFW 벤치마크 기준 **99.5% 이상의 최상급 인식률**을 제공하며, CPU에서도 10~20ms(초당 30fps 이상) 속도로 실시간 인식이 가능합니다. 코사인 유사도(Cosine Similarity) 임계값을 `0.65 ~ 0.70`으로 설정하면 등록 학생을 오차 없이 식별합니다.
> - **한글 출력**: 화면에 학생 이름 오버레이 시 OpenCV `putText`는 한글이 깨지므로 이미 설치된 **`Pillow(PIL)`**의 `ImageDraw.Draw`와 맑은 고딕(`malgun.ttf`)을 사용합니다.

```text
너는 이 프로젝트의 vision-agent다.
.agents/rules/vision-rules.md 와 .agents/skills/vision-recognition-integration/SKILL.md를 따른다.
docs/03-2차-완성-가이드-및-AI-프롬프트-핸드북.md 를 참고해줘.

현재 vision/main.py는 키보드 시뮬레이션 및 YOLOv8 감지로 동작하고 있어.
이를 고도화하여 실제 웹캠에서 학생 얼굴을 검출하고 사전 등록된 학생 임베딩 벡터와 비교하여 일치하면 face_recognized 이벤트를, 불일치하면 face_unrecognized 이벤트를 백엔드(POST /api/v1/vision/events)로 전송하도록 업그레이드해줘.

[구현 지침 - C++ 빌드 에러 방지]
1. dlib이나 face_recognition 대신, 이미 설치된 onnxruntime(경량 ArcFace ONNX) 또는 OpenCV DNN(YuNet + SFace: cv2.FaceDetectorYN, cv2.FaceRecognizerSF) 또는 mediapipe를 사용하여 얼굴 검출 및 128/512차원 특징 벡터를 추출해줘.
2. 학생 식별은 코사인 유사도(scipy 또는 numpy) 임계값 0.65 이상일 때 일치 판정해줘.
3. 개인정보 보호 규칙에 따라 원본 사진은 백엔드로 전송하지 않고 학생 ID와 신뢰도(similarity)만 전송할 것.
4. 웹캠 화면에 학생 이름 한글 오버레이 시 OpenCV 깨짐 방지를 위해 Pillow(PIL) ImageDraw와 malgun.ttf 폰트를 사용할 것.
```
